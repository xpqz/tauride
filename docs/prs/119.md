# Inline tracing inspection menus

Implements [Tauride #119](https://github.com/xpqz/tauride/issues/119), following the [Dyalog inline tracing documentation](https://docs.dyalog.com/20.0/windows-ui-guide/tracer/inline-tracing/).

Action → Inline Tracing and the tracer context menu expose the current left argument, function, right argument and axis, followed by the previous result and previous operands. They open or refocus the interpreter's existing `]IT` windows, which continue updating as execution advances. Next Primitive also works from an inspection window. Its existing shortcut is unchanged; the inspection commands have no default shortcuts, and saved custom menus remain unchanged.

Availability follows a nonempty expression highlight and the owning session's ready state. This covers inline tracing within named functions as well as Session expressions. Floating windows delegate to their owner; native application menus follow the focused session and disable inspection while a helper window is active. Menu refreshes retain the installed custom menu.

Inspection commands preserve unfinished Session input, modified history and selections, including inserted lines and partial output. The existing agent Execute path receives the same preservation for the nine recognized `]IT` commands. History limits still discard expired history. Overlapping primitive execution is rejected until the inspection finishes. Automatic inspection updates and formatting replies retain tracer focus; explicit interpreter focus requests still work.

- The browser bundle builds and its headless Chrome smoke test passes with no missing resources or console errors.
- The actual macOS Action menu opened Left Argument successfully. Context-menu construction and callbacks have automated coverage; a physical right-click could not be confirmed through the computer-use tool.
- Independent implementation reviews approved the menu/routing and session/draft changes. Diff checks pass.
