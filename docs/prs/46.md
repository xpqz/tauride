# Thread IDs in window captions

Add `{TID}` to Preferences → Title, following [Tauride #46](https://github.com/xpqz/tauride/issues/46) and [Dyalog/ride #1386](https://github.com/Dyalog/ride/issues/1386). The placeholder uses the current thread reported by `InterpreterStatus.TID`, including thread zero. It is case-insensitive, like the existing caption placeholders, and does not change the default title.

Keep `statusfields` subscribed while the caption contains `{TID}`, even when the status bar is hidden. Subscription changes also reach the interpreter while APL is busy; execution input retains its existing busy guard. Other status and debugger subscriptions retain their existing behavior. Interpreters without `Subscribe` show `?`; the caption does not start legacy thread-list polling or infer identity from the debugger selection.

Show `?` before a valid report, after disconnection, or for an invalid supplied ID. A partial report without TID retains the current ID. Releasing the status subscription clears the cached identity, and late reports while unsubscribed or disconnected cannot restore it. Re-enabling may show `?` until the next status report: Dyalog 21 does not replay an unchanged status on every subscription change.

Floating editors share the session's current thread. Caption broadcasts refresh the current mounted editor's title, preserving its object name, source filename and modified marker. New floating editors inherit the current caption; pending editors wait until their normal mount/focus path to render it.

## Protocol evidence

The repository protocol reference defines `InterpreterStatus.TID` as the current thread ID. A direct loopback probe against Dyalog 21.0.54424 received TID 0 initially. This expression creates a worker stopped at a breakpoint and produced TID 1:

```apl
⎕FX'R←FOO' 'R←10' ⋄ 1 ⎕STOP 'FOO' ⋄ {FOO}&0
```

A running worker and a successful `SetThread` reply alone did not imply a changed current TID. The implementation uses the status report rather than predicting a thread transition.

## Startup focus regression

Native regression testing exposed an existing macOS startup timer stealing focus from About, routing Edit commands back to the main editor. The timer now restores editor focus only while its native window remains active. Deterministic tests cover active and inactive native windows, a stale editor, a closed window and the browser fallback. The diagnostic test closes Log windows from the main webview so closing a window cannot destroy its own WebDriver response channel.

## Validation

- All 116 Node tests pass, including nine new caption and startup-focus tests. The startup-focus regressions fail against the previous implementation.
- The Tauri test build passes. Three native caption tests passed with Dyalog 21.0.54424 before the startup-focus fix, exercising a real stopped worker, hidden status bar, busy subscriptions and floating native window titles.
- Independent code review found no outstanding issues.
- Final native-suite validation and the physical Preferences check remain pending: the desktop locked again, and the harness could not obtain native focus. The final native rerun is not a passing result.
