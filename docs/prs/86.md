# Clear visible session history

Implement [Tauride #86](https://github.com/xpqz/tauride/issues/86), following [Dyalog/ride #824](https://github.com/Dyalog/ride/issues/824).

`View > Clear Visible History` removes completed transcript text while preserving the current draft, command recall and workspace. `CVH` has no default shortcut. The existing Session log line limit controls ongoing retention; it does not provide this one-off reset without changing preferences. No performance improvement is claimed.

## State transitions

| Session state | Clear behavior |
| --- | --- |
| Ready, ordinary bottom prompt | Retain the prompt and unsent draft, including inserted draft rows and selection. Remove completed transcript text. |
| Earlier transcript lines have unsent edits | Leave the Session unchanged and explain that those edits need finishing or cancelling first. |
| Busy, no dirty edits | Remove completed lines; retain an unfinished output line for subsequent chunks. Preserve typeahead, queued execution and read-only state. |
| Busy with unsent edits | Leave the Session unchanged. |
| Multiline input, expression input (`⎕`), text input (`⍞`) or an unknown prompt | Leave the Session unchanged and explain that the input must finish first. |
| Editor or tracer focused | Clear the associated Session when allowed; preserve editor/tracer contents and focus. |
| Disconnected | Leave the Session unchanged. |
| Reconnect | Normal interpreter log retrieval can restore old transcript text. |

Clearing neither submits input nor sends a log-deletion command. It leaves command recall and its persistent file alone. The reset is immediate, with no confirmation dialog, and resets Session Undo history, including earlier edits to the retained draft. Undo cannot resurrect removed output. Ambiguous prompt/output boundaries are left unchanged. Repeated clearing with no completed history is a no-op.

The implementation resets Monaco text and local transcript metadata together. It retains the draft's original dirty-line baselines so execution and cancelling edits still work, and ignores late line-group updates for discarded rows. It does not rewrite the existing Session line-limit mechanism. On macOS, the application-menu action is sent only to the focused Session or floating editor/tracer; floating windows forward it to their owning Session. Preferences and other helper windows do not clear a background Session.

## Validation

- The initial seven regressions failed against the unchanged application because the command/menu did not exist.
- Six clear-history integration tests pass in the actual Tauri webview with Dyalog 21.0.54424: retained multirow draft and caret, execution and workspace, command recall and interpreter log retrieval, immediate Undo, historical-edit refusal, capped history, continued busy output, partial output/backspace handling, discarded line-group updates, input-state refusal and menu/shortcut registration.
- A separate real-Tauri event-delivery check with two interpreter sessions confirms the window-scoped event clears only its intended Session, preserves the other Session's text/history/draft state, and explains a disconnected refusal. This exercises event transport, not OS focus selection.
- All 126 Node tests pass. The final Tauri test build and zero-footprint build/Chrome smoke test pass.
- Independent tests and implementation review approved the change. Syntax and diff checks pass; existing repository-wide lint/format findings remain outside this change.
