# Array-notation keys before in-prefixed values

Fixes [Tauride #129](https://github.com/xpqz/tauride/issues/129), the remaining colouring edge case also addressed by [upstream Ride #1410](https://github.com/Dyalog/ride/pull/1410).

In `x←(a:input ⋄ b:2)`, the key `a` received ordinary global-variable colouring; adding a space after its colon changed the colouring. The identifier tokenizer now accepts any following colon inside array notation while retaining the `:In` exclusion in ordinary APL. Existing array-notation delimiters, label boundaries and dfn guards keep their handling.

## Validation

- Tests were written first and independently reviewed. The unchanged tokenizer failed both new provider regressions with `identifier.global.apl` instead of `identifier.local.aplan.apl`; the other 53 focused tests passed. All 55 pass with the fix.
- Regressions cover compact and spaced pairs, mixed-case in-prefixed values, keys after diamonds, multiline arrays, ordinary `:For` with `:In` and `:InEach`, labels and dfn guards.
- All 252 unit checks pass across the full run and the harness retry. The initial sandboxed run passed 245 and failed seven harness checks because localhost listeners were forbidden; all nine harness checks passed with localhost access.
- The new native regression failed against the unchanged test app for the same incorrect key scope. All six Monaco native tests pass against the rebuilt app with Dyalog 21.0.54424. The new case checks registered token scopes and rendered key colours in APL, APLAN and Session models using isolated preferences and interpreter processes.
- A window-only screenshot of the running test app confirmed identical colouring for compact and spaced keys with distinct key/value theme colours.
- The shared browser bundle builds and its headless Chrome smoke check passes with no missing resources or console errors.
- Independent implementation review approved the change. JavaScript syntax and diff checks pass.

The production change is one conditional in the shared tokenizer. No platform-specific runtime code changes are needed. Native validation was performed on macOS; Windows and Linux use the same tokenizer and receive build coverage in CI.
