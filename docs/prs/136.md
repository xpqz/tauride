# Use asynchronous native desktop services

Tracking issue: [#136](https://github.com/xpqz/tauride/issues/136).

Desktop alerts, confirmations and file pickers previously used synchronous `ridesync://` requests, even through the Promise-shaped compatibility APIs. A modal dialog could therefore block the webview until it was dismissed. The asynchronous APIs now invoke native commands and resolve when the user responds. Tauri's dialog plugin handles simple messages and file pickers; richer message options retain the platform implementation needed for custom button indices, default/cancel choices and checkboxes. On macOS, rich dialogs use an owned sheet with a completion callback; the synchronous extension API retains its modal implementation.

Close confirmation now waits for consent before exiting or disconnecting. Repeated close requests share the pending decision, and late replies cannot act on a replaced or disconnected session or a removed editor. The old three-second native close bypass is removed because it could destroy a window while its confirmation was pending or immediately after Cancel. Editor cancellation keeps the modified text. Connection-file overwrite confirmation and file selection also wait for the user's response before applying changes.

Tauri's opener plugin replaces the separate OS command implementations for opening URLs and files and revealing a selected file in its folder. The compatibility layer retains its public API shapes and synchronous extension entrypoints. Browser-only Ride retains its existing dialogs.

Regression coverage exercises deferred responses, cancellation, failure and stale owners. Native tests check JavaScript responsiveness while actual dialogs are pending. The PR records final native, unit and platform build results, including integration with the startup-diagnostics and Electron-retirement changes.
