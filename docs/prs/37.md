# #37: Resume inbound dispatch after a handler exception

A scheduled rundown could throw before resetting its timer marker, permanently
preventing later messages from reaching their handlers. The rundown now resets
scheduling state in `finally` and schedules one continuation when unblocked
messages remain. The original error still propagates. The failed message or output
batch has already been consumed and is not retried; later messages retain their
order and existing output batching.

Validation on 10 October 2026:

- Tests were written and independently reviewed before implementation. Five #37
  regressions failed on the baseline: future and already-queued messages after a
  scheduled throw, block/unblock recovery without spinning, preserved batching and
  command order, and recovery after the session output append throws. The
  synchronous first-message exception control already passed.
- `node --test tests-node/async-recovery.js tests-node/session.js`: 29 passing tests.
- Queue tests execute the actual queue functions with deterministic timer callbacks,
  assert the original error object is exposed, and require no extra incoming
  message to resume work already queued behind a failure.

Independent implementation review approved the change. Native macOS Tauri/WKWebView
validation injected a throwing handler with another message already queued behind
it. The original error appeared once, the queued message ran once, and a subsequent
live Dyalog expression produced `fixed-queue-4` in both the incoming protocol and
Monaco session model. No additional uncaught errors appeared during this probe.
Results are recorded in `/private/tmp/tauride-36-41-native-results.json`.

The full 99-test unit suite, Tauri build, and shared browser build/smoke check pass.
There are no new source ESLint diagnostics, and `git diff --check` passes. The
screen was locked, so this verifies command/protocol handling, not physical input.
The original native transport-versus-display proof is documented in
[the upstream review](../upstream-issue-review-2026-10-10.md). This fix does not
establish the cause of unrelated historical disconnects or recover side effects
of the failed handler.
