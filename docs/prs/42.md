# #42: Show interpreter input state in the status bar

The status bar now labels the interpreter's current input state, so a ready prompt, expression input (`⎕`), text input (`⍞`), and multiline input are distinguishable. The existing clock icon accompanies Busy; other states use text alone. The full label remains in the tooltip when the visible text is truncated.

## State mapping

Conditions are applied in this order:

| Condition | Label |
| --- | --- |
| Floating editor | Indicator hidden |
| Session disconnected | Disconnected |
| Not identified, or no prompt notification received yet | Interpreter unavailable |
| Prompt type 0 | Busy |
| Prompt type 1 | Ready |
| Prompt type 2 | Enter expression (⎕) |
| Prompt type 3 | Multiline input |
| Prompt type 4 | Enter text (⍞) |
| Prompt type 5 | Awaiting input |
| Other prompt type | Input status unknown |

Compact status-bar examples:

```text
Ready                  │ ⎕IO: 1 │ ⎕ML: 1 │ Pos: 0/1,6
◷ Busy                 │ ⎕IO: 1 │ ⎕ML: 1 │ Pos: 0/1,6
Enter expression (⎕)   │ ⎕IO: 1 │ ⎕ML: 1 │ Pos: 0/1,6
Enter text (⍞)         │ ⎕IO: 1 │ ⎕ML: 1 │ Pos: 0/1,6
```

`updateInputState()` owns the display and runs at construction, identification, prompt changes, and disconnection. A display-only `promptReceived` flag prevents the existing initial `promptType = 1` from presenting an unconfirmed Ready state. Execution and input semantics retain the existing prompt value. Disconnection takes precedence over late prompt or identity messages; hiding the status bar does not stop label updates. Floating editors hide the indicator because their session prompt state is not synchronized.

The indicator uses `role="status"`, `aria-live="polite"`, and `aria-atomic="true"`. The clock is decorative. The label has priority over metrics in narrow windows; its text can ellipsize, while the metrics remain on one line and are clipped within their own region. Browser WebSocket closure calls die() on the IDE captured for that connection.

## Validation

Four unit regressions and two native regressions failed before implementation. Independent tests-only and implementation reviews approved the change.

- `npm run test:unit`: 106 passed.
- `npm run test:build`: passed.
- `npm test -- test/input-state.js`: 2 passed with real interpreter sessions and webviews using programmatic submission. Coverage includes prompt transitions, read-only behavior, accessibility attributes, hidden-bar updates, narrow layout, unknown states, and disconnection precedence.
- Visual inspection passed at normal size and at 320px width with zoom 8.
- CSS compilation, JavaScript syntax checks, and whitespace checks passed.

Unit coverage also verifies initial unavailable-state derivation, floating editors, recoverable errors, and browser socket ownership. Constructor wiring was reviewed. Native CUA keyboard entry verified Busy then Ready with `⎕DL 3`, text input with `auditPhysicalText←⍞` and a reply, expression input with `auditPhysicalValue←⎕` and `2+2`, and multiline input with `∇auditPhysicalFn` followed by a closing `∇`. Each displayed the correct label. macOS accessibility exposed the current full status labels.

VoiceOver was enabled with its caption setting already on, but CUA timed out accessing the caption window, so spoken announcements remain unverified. VoiceOver was turned off afterward and its Utility closed. Interpreter protocol and command submission behavior are unchanged.
