# #45: Trace/Edit toolbar visibility in View

The default View menu now includes a checked **Show Trace/Edit Toolbar** action. The new `TTB` command is assignable in Shortcuts and has no default binding. Both use the existing `showEditorToolbar` preference, so menu actions, Preferences and commands share one saved setting. The existing editor initialization and preference IPC apply it to current and newly opened docked/floating editors and tracers.

The preference listener also rebuilds the application menu, which updates the real macOS menu checkmark after changes from shortcuts or other windows. Custom saved menus remain untouched; they can add `Show Trace/Edit Toolbar =TTB`, or restore the default menu through Preferences.

## Validation

- Both new Node tests fail against baseline `15f1452a` because the View command is missing; they pass with this change. They exercise menu/preference/command state, dispatch without a focused editor, and the assignable command with no default shortcut.
- `npm run test:unit`: 102 passed.
- `npm run test:build`: passed.
- All four `test/cn.js` native tests with the existing macOS test binary passed, including interpreter startup. Favourite tests also verify the saved connection names.
- `npm test -- test/toolbar.js` with the freshly built test binary: two native macOS tests passed. They cover current/new docked editors and tracers, checked-menu refresh, existing/new floating windows, and preference changes propagated through real IPC in both directions.
- Changed production files have no new ESLint diagnostics compared with the baseline; syntax and diff checks pass.
- Independent implementation and test review found no material issues.

Automated native tests inject OpenWindow messages into an isolated app, use real Monaco instances and native webviews, and invoke menu actions and commands in JavaScript. A separate physical macOS check confirmed that View > Show Trace/Edit Toolbar hid a docked editor's toolbar. Recording `Shift+Cmd+Y` in Preferences > Shortcuts and saving it let the actual key chord restore the toolbar. The Trace/Edit Show toolbar checkbox reflected that setting; clearing it and saving hid the current editor's toolbar. Physical floating-window follow-up was blocked by a screen-capture error; floating-window coverage is automated.

The harness sets `LOG_FILE` to `dyalog*.dlf` inside each temporary profile, overriding inherited interpreter log paths while preserving HOME. The native audit confirmed a clean session startup and creation of `dyalog000.dlf` in that profile.

## Linux CI startup

The embedded WebDriver plugin supports Linux as well as macOS. Its status endpoint reports ready only after a webview is registered. The earlier Linux connection-test timeout hid both HTTP responses and request errors; readiness timeouts now include the last status response or connection error code. A regression test distinguishes an initializing webview from an unreachable server.

The Linux startup backtrace identified a synchronous D-Bus desktop-portal theme query in Tao's GTK window constructor, before Tauri registered the webview. The Linux connection tests now run through `dbus-run-session` inside Xvfb, giving the app a private session bus with the virtual display inherited. The readiness diagnostic remains useful for future startup failures.

The Linux favourite tests also exposed a WebDriver input mismatch. With no local interpreters, the initial connection is unnamed; WebDriver's clear-before-type command dispatched a change while the new favourite was still unnamed, opening the real duplicate-name dialog. The input helper now applies the complete value and dispatches input/change once. Tests still run the application's save handlers and additionally verify the saved connection names in `connections.json`. No production behavior or test deadlines changed.
