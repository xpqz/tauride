# Give an attached agent the context of the last error

Implements [Tauride #149](https://github.com/xpqz/tauride/issues/149). Branch `claude/149-last-error`.

The pairing interface gains `last_error`: it answers the frozen diagnostic context of the latest captured error, or of the error named by `error_id`, with its `stale` flag. It is the same bundle the error explanation providers receive. An attached agent can then explain an error in its own conversation without a companion.

- `src/agent_core.js`: the request at `observe`, settled like the other reads; `error_id` is optional and is the capture's id string (`error-3`); `not_found` when no error has been captured or the id is unknown or evicted.
- `src/error_context.js`: `captured(timeout)` resolves once the latest error is frozen, cleared or superseded, or at the deadline.
- `src/agent.js`: `io.lastError(id)` waits up to a second for an error still being captured, then reads the capture; without the wait a request straight after an error answered `not_found`. Capture runs only while observation is on, and the socket is closed while it is off, so no bundle is served then.
- `tools/tauride-mcp/tauride-mcp.js`: the MCP tool `last_error` (optional `error_id`) and the CLI command `last-error [id]`.
- `tauri/agent-pairing.md`: the request's row, and how an attached agent uses it.
