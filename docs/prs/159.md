# Codex setup tests fail intermittently under load

Implements [Tauride #159](https://github.com/xpqz/tauride/issues/159). Branch `claude/159-codex-setup-tests`.

Two Codex tests in `src-tauri/src/companion.rs` bounded the setup probe tightly enough that the Python Codex double's own startup could exhaust the bound under load, so they failed on a missing `.pid` file or an `unavailable` status that was not the outcome under test. Test code only; no product timeout changes.

- `setup_probe_is_private_has_no_inference_and_reaps_every_outcome`: modes in which the double answers get a 15 s bound; the timeout modes (`wait`, `initwait`) get 3 s, far below the double's 60 s sleep, so they still time out.
- `provider_setup_finishes_and_reaps_independently_after_session_close`: the probe's bound is 5 s and the wait for the double's pid 10 s, sleeping between polls instead of spinning.

Every assertion is unchanged.
