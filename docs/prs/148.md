# Explain errors with a user-defined command

Implements [Tauride #148](https://github.com/xpqz/tauride/issues/148). Branch `claude/148-command-provider`.

Adds a `command` error-explanation provider, "Custom command": a user-chosen program and arguments that read the explanation prompt on stdin and write the explanation to stdout, for agents without a dedicated provider (Gemini CLI, `llm`, `ollama run`).

## Design

- Settings are `executable` and `args`, one argument per line, with no shell; blank lines are skipped and a trailing `\r` is ignored. A pipeline needs `/bin/sh` with `-c`. The descriptor gains `supports_args`, which only this provider sets; the Rust configuration, Preferences and the panel accept `args` only for such a provider. There is no model setting: a model belongs in the arguments.
- stdin carries the whole prompt as one text: base instructions, developer instructions and the user prefix with the snapshot, separated by blank lines; stdin is then closed.
- stdout is streamed to the panel as it arrives, decoded as UTF-8 without splitting a character across deltas, under the shared output limit.
- The command runs in its own process group in an empty private working directory. Cancellation, disabling observation and session close end the whole group, so what the command started ends with it.
- Exit status 0 with text is an explanation. A non-zero exit is an error carrying at most 4 KiB of stderr. Exit 0 without text is an error. A command that closes stdout but does not exit within a grace period is ended and reported as not exiting.
- `enforces_no_tools: false`: the panel says Tauride cannot prevent the command from using tools or taking actions.
- The setup check reports `ready` when the executable resolves on `PATH` or as a path, `missing` otherwise, including when none is set. It never runs the command.

| Mutation | Fails |

| each chunk decoded on its own | `command_output_is_streamed_as_text_without_splitting_characters` |
| no process group of its own | `cancel_and_terminate_end_the_command_and_what_it_started` |
| `stop` leaves the group | `cancel_and_terminate_end_the_command_and_what_it_started` |
| all of stderr kept | `command_failures_never_become_explanations` |

| setup `ready` without a resolvable executable | `command_setup_checks_only_that_the_executable_resolves` |

A separate strip of a trailing `\r` survived its removal, because `str::lines` already drops it, so it was deleted. The cancel test gained a guard that kills the command's child if the test fails, after two failing mutation runs left one running.

## Live run

Through the provider code (a temporary ignored test, not committed) with `claude` as the custom command and the arguments `-p`, `--model=haiku`, `--tools=`, `--strict-mcp-config`, `--setting-sources=`, `--no-session-persistence`: a correct explanation of `1 2 3+4 5`, complete in 9.9 s. `claude -p` prints its text when done, so it arrived as one delta.

## Noted

- Two Codex tests in `companion::tests`, `setup_probe_is_private_has_no_inference_and_reaps_every_outcome` and `provider_setup_finishes_and_reaps_independently_after_session_close`, fail intermittently on unmodified `main` (6 and 2 of 8 runs on this machine under load): their 500 ms and 3 s bounds can elapse before the Codex double has started.
- A command that never closes stdout is ended by the shared 120 s explanation timeout, or by cancellation; no test waits for the timeout.
