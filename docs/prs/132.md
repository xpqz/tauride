# Native startup transport and diagnostics

Tracking issue: [#132](https://github.com/xpqz/tauride/issues/132).

The native harness has intermittently timed out on ordinary WebDriver element lookup and script execution during Session startup. The application produced no output, leaving the failed readiness phase and native process state unknown.

## Investigation

The installed `tauri-plugin-wdio-webdriver` 1.5.0 implements ordinary macOS evaluation with a `WKWebView.evaluateJavaScript` completion handler. Its public `/wdio/eval` endpoint provides a separate result channel through `WKScriptMessageHandler`. The upstream embedded service uses this endpoint for execution; it already contains recovery for documented WebKit completion problems. See the [upstream execution implementation](https://github.com/webdriverio/desktop-mobile/blob/main/packages/tauri-service/src/commands/execute.ts) and [upstream investigation](https://github.com/webdriverio/desktop-mobile/issues/540).

Both routes select the same `main` webview and empty frame context during startup. The app creates helper windows without navigating the main page. Splash dismissal can precede IDE creation, but a missing tab should return zero matches rather than leave its HTTP request unanswered. No session-lock deadlock or window-target mismatch was identified.

Forty consecutive native Session launches and all 86 cases in the full native suite passed using the original WebDriver readiness routes with diagnostics added. Every repeated launch also completed an ordinary script command afterward. The final process inventory contained no new Tauride, Dyalog or Dyalog helper processes. This does not establish the cause of the three earlier intermittent failures.

## Failure evidence

Startup failures retain their original error and add the current phase, elapsed time, owned app PID and the last successful frontend snapshot. Before teardown, a bounded read-only DirectEval probe checks whether the main page still responds, and macOS samples the owned live process. The temporary profile is removed; a separate diagnostic directory retains the JSON state, bounded app output and native thread sample.

Snapshots contain readiness, connection-screen and main-page dialog visibility, and geometry metadata, not editor text or environment variables. Diagnostic failures annotate the original error and do not prevent cleanup.

## Startup transport

Read-only startup snapshots now use the embedded driver's supported DirectEval endpoint. The four readiness requirements remain: a fully loaded Tauride page with its window manager, a dismissed splash, an active IDE tab, and a Session model with input prompt type 1. Connection-screen tests require only the first two. Each phase still has a 30-second deadline, with script and HTTP requests bounded to at most 10 seconds and the remaining phase time.

Only a valid, not-yet-ready snapshot is polled again. HTTP failures, script exceptions and malformed snapshots fail immediately; the harness does not restart the app or fall back to a different readiness route. Upstream DirectEval can redispatch after a lost native completion, so these checks must remain read-only. Commands after startup, including shutdown, retain ordinary WebDriver execution.

This is a targeted transport adaptation backed by the upstream implementation and deterministic stalled-transport tests. It does not establish that WebKit callback reclamation caused the original three failures. Session creation still uses the driver's ordinary native evaluation path, and later WebDriver commands are outside this change. Issue #132 remains open for that native diagnosis.

## Validation

- The regression fixture first failed against the standard readiness transport: the held ordinary endpoint timed out during frontend startup. The same fixture passes through DirectEval while still requiring every readiness condition.
- All 272 Node tests pass, including 25 harness tests. Coverage includes connection startup without a Session, false readiness, script and HTTP errors, malformed snapshots, bounded stalled requests, diagnostic failures, immutable timeout exceptions and owned-process cleanup.
- Forty consecutive Session launches pass with the new transport; an ordinary WebDriver command succeeds after each launch. No new Tauride, Dyalog or helper processes remain afterward.
- Independent implementation and adversarial test reviews have no outstanding findings. The pull request records the final full native-suite and CI results.

Native validation uses macOS 27.0.1 and a fresh `ui-tests` binary built from this branch's unchanged application sources. No production application code or dependency version changed.
