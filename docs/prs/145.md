# Explain APL errors with a provider companion

Implements [Tauride #145](https://github.com/xpqz/tauride/issues/145).

Agent > Explain Last Error… and the specific-line Explain This Error… context menu collect a bounded diagnostic snapshot and stream an explanation and suggested correction into Tauride. The AGE command is available to custom menus and key mappings without a new default shortcut. First use checks Codex installation and sign-in and provides setup guidance, an observation toggle, and a direct Preferences link. Preferences selects a provider and keeps its executable and model overrides under Advanced. Codex is the only registered provider in this change. Setup checks do not submit diagnostic data or start inference. An explanation requested from a floating tracer raises the owning session and focuses the panel; streaming does not move focus. Backtick-delimited inline code and fenced code blocks render with the APL font; other markup remains literal text, including HTML. Incomplete delimiters remain visible until the stream supplies their closing delimiter.

Independent review approved the extraction and its test-edit ledger.

The companion reuses the user's Codex authentication and stays warm between requests, with a new ephemeral conversation for each error. It does not occupy Tauride's MCP socket. Explanation requests disable inherited tools and use read-only permissions; this change does not apply edits or execute suggestions. Cancellation, disabling observation and session shutdown release the owned work.

Historical context retains the error's identity and captured data. Resuming execution or changing the selected frame marks it stale, and missing stack/value data is explicitly unavailable. Saved source and modified buffers are distinct.

## Provider extraction

An object-safe `Provider` trait separates the session lifecycle from the Codex
JSON-RPC implementation. The process identity contains provider id and
executable. Model is passed per request, so changing it neither restarts the
warm process nor invalidates the setup cache. `Session` retains immediate
access to the active child for cancellation and teardown. A provider that
starts one child per request can stop and clear it without turning a successful
explanation into an error.

Setup creates an independent provider instance, sends no diagnostic data and
starts no inference. It runs to its own timeout and cleans up after itself;
closing the panel discards its result. Only explanations are subject to
session cancellation and cleanup.

`companion_providers` supplies descriptors to both the panel and the Preferences
helper. These drive names, model availability, setup guidance, documentation
links and truthful tool-enforcement disclosures. `agentProvider` and the
validated per-provider `agentProviderSettings` map replace the old preferences
and controls outright, without migration. AGE is `Explain Last Error…` in the
command catalogue and default menu. The specific-error context menu is
`Explain This Error…`. Codex-specific protocol
errors retain their names; shared lifecycle errors use the selected provider.

No Claude or command provider and no `last_error` request are implemented.
The design and deferred work are in `tauri/agent-providers.md`.

## Final review adjustments

- A registry lookup selects and validates one provider and returns its descriptor
  and unstarted instance together. Warm reuse discards an unused candidate
  without stopping it; unstarted providers must not own or kill the session's
  existing child. Process identity still excludes model.
- `Provider::reusable` determines retention after a successful request. Session
  no longer checks child presence or descriptor warmth; Codex keeps its existing
  conditions within the adapter. Tests exercise both reuse without a child and
  non-reuse with a child present, independently of the descriptor's `warm` flag.
- The specific-error context-menu label and its native test literal are
  `Explain This Error…`; AGE remains `Explain Last Error…`.
- At the user's request, the capture test now reads `package.json`'s `version`
  instead of the literal `4.8.4`, with its introductory comment updated to
  describe that exception. No protocol or prompt assertion is removed or
  weakened. The unchanged before/after extraction proof above remains valid
  for commits `992a404f` and `2f578712`.
- `SetupGuidance.ready` is removed because the frontend does not display it.
  Its serialization assertion now checks absence; the `ready` setup status and
  readiness message are unchanged. Registry and Session test setup is adapted
  mechanically to the paired provider lookup and changed execute signature.
  An additional assertion confirms that discarding an unstarted candidate
  leaves the existing warm process alive.

Noted items, intentionally unchanged in this review:

- The output limit is enforced twice: by the Codex protocol stream and by the
  shared Session emitter.
- Codex's `unavailable` guidance repeats its `signin` guidance.
