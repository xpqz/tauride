# Explain APL errors with a provider companion

Implements [Tauride #145](https://github.com/xpqz/tauride/issues/145).

Agent > Explain Last Error… and the error context menu collect a bounded diagnostic snapshot and stream an explanation and suggested correction into Tauride. The AGE command is available to custom menus and key mappings without a new default shortcut. First use checks Codex installation and sign-in and provides setup guidance, an observation toggle, and a direct Preferences link. Preferences selects a provider and keeps its executable and model overrides under Advanced. Codex is the only registered provider in this change. Setup checks do not submit diagnostic data or start inference. An explanation requested from a floating tracer raises the owning session and focuses the panel; streaming does not move focus. Backtick-delimited inline code and fenced code blocks render with the APL font; other markup remains literal text, including HTML. Incomplete delimiters remain visible until the stream supplies their closing delimiter.

Independent review approved the extraction and its test-edit ledger.

The companion reuses the user's Codex authentication and stays warm between requests, with a new ephemeral conversation for each error. It does not occupy Tauride's MCP socket. Explanation requests disable inherited tools and use read-only permissions; this change does not apply edits or execute suggestions. Cancellation, disabling observation and session shutdown release the owned work.

Historical context retains the error's identity and captured data. Resuming execution or changing the selected frame marks it stale, and missing stack/value data is explicitly unavailable. Saved source and modified buffers are distinct.

## Provider extraction

An object-safe `Provider` trait separates the session lifecycle from the Codex
JSON-RPC implementation. The process identity contains provider id and
executable. Model is passed per request, so changing it neither restarts the
warm process nor invalidates the setup cache. `Session` retains immediate
access to the active child for cancellation and teardown. A provider that
starts one child per request can stop and clear it without turning a successful
explanation into an error.

Setup creates an independent provider instance, sends no diagnostic data and
starts no inference. It runs to its own timeout and cleans up after itself;
closing the panel discards its result. Only explanations are subject to
session cancellation and cleanup.

`companion_providers` supplies descriptors to both the panel and the Preferences
helper. These drive names, model availability, setup guidance, documentation
links and truthful tool-enforcement disclosures. `agentProvider` and the
validated per-provider `agentProviderSettings` map replace the old preferences
and controls outright, without migration. AGE is `Explain Last Error…` in the
command catalogue, context menu and default menu. Codex-specific protocol
errors retain their names; shared lifecycle errors use the selected provider.

No Claude or command provider and no `last_error` request are implemented.
The design and deferred work are in `tauri/agent-providers.md`.

## Validation

Baseline before changes: all 306 Node unit tests passed. New context, UI and companion tests were written and observed failing before implementation; tests and implementation received independent review.

- 362 Node unit tests and 32 Rust tests with the CI feature set pass after extraction. New coverage includes process identity/model reuse, executable restart, cold-process cleanup, setup independence, shared output bounds, per-provider validation and capability-driven disclosure. The earlier implementation also passed 24 MCP adapter tests.
- The initial implementation passed 13 native macOS/Dyalog tests, including existing agent confirmation and multi-session menu routing. Error-help cases cover: disabled observation, historical error targeting/native menu dispatch, HTML rendered as text/MCP coexistence, cancellation/retry/process cleanup, actual saved source/stack/local previews, and floating tracer ownership.
- The setup probe also reports ready against the installed Codex runtime without sending context or starting inference.
- All eight native error-help tests pass after extraction, including the unchanged pre-extraction request capture. The seven existing cases cover first-use observation, missing and signed-out Codex, explicit rechecking, Advanced preferences, code formatting, and existing tracing/cancellation flows. The earlier native panel screenshot was inspected. Setup-probe regressions cover privacy, no inference, timeout cleanup, PATH executables, and isolation from the warm companion.
- Browser Ride builds and passes its Chrome smoke test.
- A live run using Dyalog 21.0.54424, Codex 0.162.0-alpha.17.2 and `gpt-6.1-sol` correctly explained a vector LENGTH ERROR and an undefined-name VALUE ERROR. No suggested code was executed.

| Request | First streamed text¹ | Click to completion |
| --- | ---: | ---: |
| Cold companion, LENGTH ERROR | 3.96 s | 6.52 s |
| Warm companion, VALUE ERROR | 3.38 s | 5.77 s |

¹ Measured from acceptance by the native command; the UI opens its progress panel immediately. These are two observations, not a latency guarantee. They exceed the aspirational two-second first-text target; model and network latency remain significant.

During the initial live validation, standalone Codex 0.144.1 could not run the user's configured `gpt-6-astra`; the panel surfaces that compatibility error. The live test selected the newer app-bundled executable in an isolated test profile. Normal user preferences and authentication were not changed.

Native integration was exercised on macOS. Linux/Windows compilation and portable unit coverage run in CI; native desktop interaction on those platforms remains unverified. The deterministic subprocess fixture tests require Unix. UI scenarios drive the real app through its test interface, including native menu dispatch; no claim of manual keyboard/screen-reader verification is made.
