# #36: Keep Workspace Explorer replies with their owning tree

A value tip from the previous tree could decrement a new refresh's pending count,
install its incomplete root, and throw. Bonsai now checks the owning tree map and
node before applying replies, and does not request outgoing-tree tips during a
refresh. Current children and values continue to render after their own replies.

The actual WSE/IDE route also reused node IDs for asynchronous requests. WSE now
uses a unique local request ID for each value tip and its timeout. TreeList replies
carry only a node ID, so WSE queues callbacks and permits one request per node in
flight. It removes the completed callback before invocation, preserving requests
made by that callback. Closing and reopening the panel retains the WSE instance,
so pending requests and timeouts keep the same owner; the panel still refreshes on
each toggle. Bonsai's DOM event properties survive reattachment, and each new layout
container gets its own tab callback. This does not claim to identify arbitrary duplicate replies
or recover a TreeList request for which the interpreter never replies.
