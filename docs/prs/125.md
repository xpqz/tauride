# Preserve connection window size in fullscreen and maximized modes

Implements [Tauride #125](https://github.com/xpqz/tauride/issues/125).

Opening or closing connection configuration details preserves the fullscreen
or maximized window's geometry and mode. The Tauri window adapter checks the
native mode before applying its temporary size constraints or resizing.
The same check covers pending size requests applied when a hidden window is
shown. Ordinary windows retain queued resizing, minimum-size restoration and
pending hidden-window requests. The Electron adapter is unchanged.

The temporary maximum-size constraint previously clamped the macOS fullscreen
window to the connection screen's saved ordinary width. The baseline native
reproduction kept fullscreen active but narrowed the content from 1800 to 900
logical pixels, leaving the remaining fullscreen area black.

Saved fullscreen geometry and connection-state persistence are outside this
change's scope.

## Validation

Tests were added and reviewed before the implementation:

- The window-sizing unit tests failed in four fullscreen/maximized cases;
  the two ordinary/hidden-window cases passed against the baseline.
- Both native cog regressions passed their ordinary-window positive controls,
  then failed against the baseline: fullscreen width fell from 3600 to 1800
  physical pixels, and the maximized cog toggle left maximized mode.
- One earlier native run lost its app process during the ordinary-window
  positive control and reported ECONNREFUSED. A fullscreen-only rerun reached
  the expected width failure.

The native tests check repeated opening and closing, unchanged window and
viewport dimensions, retained native mode, and working panel toggles after
restoring an ordinary window. The ordinary-window positive controls require
expansion to increase width and collapse to restore the captured width without
changing height.

Post-implementation validation:

- All 244 JavaScript unit tests pass, including the six window-sizing cases.
- The first fixed native run passed both new tests' ordinary-window and repeated
  fullscreen/maximized sizing assertions, and all ten existing targeted cases.
  The new tests then rejected the restoration call because the installed
  WebdriverIO API requires positional arguments. Both new tests pass after
  correcting that call, completing all 12 targeted native regressions on macOS.
- A separate native reproduction preserves both the 1800 × 1130 logical content
  size and viewport after opening details; the rendered fullscreen view was
  captured and visually checked.
- Independent tests-first and implementation reviews approved the final changes.
- Windows and Linux were not physically tested.
