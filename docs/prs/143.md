# Restore vertical window resizing

Issue: https://github.com/xpqz/tauride/issues/143

## Problem

On macOS, a Tauride connection window restored at a tall saved size could be widened but could not be shortened. The constraint also survived the transition into a session.

The connection page calculated its minimum width using `winstate.dx`, an Electron frame-width offset absent from Tauride's window state. The resulting `NaN` was rejected by Tauri's native minimum-size command. The window adapter temporarily pinned both dimensions while resizing; its later attempt to restore that invalid minimum failed, leaving the current height as the minimum.

A diagnostic launch with a saved 907 × 1078 window reported a native minimum of 907 × 1078. Tracing a subsequent resize showed the restore request contained a null width and failed native argument validation. Setting a valid 400 × 400 minimum directly succeeded.

## Change

Use the connection page's existing 400/885 content-width minima directly. Preserve the 400 minimum height, queued window sizing and fullscreen/maximized behavior.

The test-only native window-state command now exposes macOS content-size constraints. The regression checks those constraints before testing growth and shrinkage; programmatic resizing alone passed on the broken version because it bypassed the interactive minimum.

## Validation

- The new frontend regression failed before the fix with a `NaN` minimum width.
- The new native regression failed before the fix with a pinned minimum width of 900 rather than 885; the saved-state diagnostic separately confirmed the locked minimum height.
- All 306 unit tests pass after the fix.
- Independent implementation and test review found no blocking issues.
- All 11 targeted native UI tests pass: connection forms, normal/fullscreen/maximized connection sizing, docked/floating editors, session, Preferences and About layout.
- A fresh app with the same tall saved geometry reports a 400 × 400 native minimum. Native Zoom restores the smaller connection window, and macOS Top Half reduces a running session from height 1078 to 541 logical pixels.
- Direct border-drag verification was inconclusive: the UI tool could not reliably target the outer border. The native constraint checks and OS sizing actions provide the interactive-resize evidence.
- Interpreter-process inventory is unchanged after testing: 32 pre-existing processes, no added or missing processes.
