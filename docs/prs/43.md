# #43: Copy and find diagnostic text

The About details and protocol log are readable diagnostic text. Both windows expose **Copy** for the current selection, **Copy All** for the complete current text, and **Find**. Copy is unavailable with an empty selection and never silently copies everything. Keyboard Copy and the Edit or context menu Copy act on the focused diagnostic field, including a selection in the Find query. The text remains read only.

Find uses literal, case-insensitive matching. Enter and Shift+Enter move to the next and previous match, and the visible controls do the same. Navigation wraps at either end. The window reports the current match and total, or an explicit no-match state. Escape closes Find first; a second Escape closes About. About has Find because its preferences dump can be long, and sharing this behavior with Log keeps the controls predictable.

The log continues to append while open. Appends preserve a reader's text selection and current search match. The view follows new output only when it was already at the bottom and the reader is neither selecting text nor searching; browsing an earlier part of the log must not jump. Closing the log removes its listener.

## Implementation

A shared textarea controller provides selection, search, match scrolling and append behavior. Both standalone pages and the browser About dialog use it. Native Find and Select All events target the active diagnostic window; the listener is scoped to that window so a second Log cannot receive its commands. Electron dispatch uses the actual focused window and supplies the diagnostic context menu.

Upstream requests: [Dyalog/ride #1295](https://github.com/Dyalog/ride/issues/1295), [#1296](https://github.com/Dyalog/ride/issues/1296), [#1297](https://github.com/Dyalog/ride/issues/1297).

## Regression boundary

`test/diagnostic-text.js` exercises the real Tauri windows and system clipboard. About coverage distinguishes Copy from Copy All, checks empty selection, case-insensitive Find, match counts, both navigation directions, no-match feedback, query-field Copy, and Escape handler behavior. Log coverage opens the actual protocol log, searches protocol text, then checks that matching appends retain the current occurrence and update the count. It also checks manual selection, scroll position while browsing, Copy All after appends, and tail following. A macOS-only test invokes actual installed Edit-menu item IDs through a test-only Rust command and checks routing to About, two simultaneous Logs, and the main editor. Keyboard handler checks dispatch DOM events; the native menu routing test requires desktop focus. Tests retain their own window handles because the app also has hidden utility windows.

## Validation

- Tests-first baseline failed all three diagnostic cases before implementation.
- All three native diagnostic tests pass against a real Dyalog interpreter. The selected connection, docked-toolbar, and input-state regressions also pass. The floating-toolbar case times out at editor initialization on both this build and the pre-change binary; it is not claimed as passing.
- All 106 Node tests pass. The browser package builds and its Chrome startup smoke passes.
- A separate headless browser audit checks About selection, clipboard payloads at the copy boundary, query focus, match navigation, distant results, and menu routing. It passes.
- Physical macOS checks with the isolated test app verify About and Log Find shortcuts/typing/navigation, selected-text keyboard Copy, Log Edit → Find, About Select All, and About's native Copy context menu. The clipboard contains the selected Log word after Cmd+C. About and Log layouts were inspected.
- Electron context-menu integration is source-reviewed; Electron and Windows/Linux desktop interaction have not been exercised locally.
- Local dependency installation required `npm ci --legacy-peer-deps` because the existing lock includes an old Puppeteer transitive dependency that conflicts with WebdriverIO's optional peer. This change does not alter dependencies.
