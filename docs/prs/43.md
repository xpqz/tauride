# #43: Copy and find diagnostic text

The About details and protocol log are readable diagnostic text. Both windows expose **Copy** for the current selection, **Copy All** for the complete current text, and **Find**. Copy is unavailable with an empty selection and never silently copies everything. Keyboard Copy and the Edit or context menu Copy act on the focused diagnostic field, including a selection in the Find query. The text remains read only.

Find uses literal, case-insensitive matching. Enter and Shift+Enter move to the next and previous match, and the visible controls do the same. Navigation wraps at either end. The window reports the current match and total, or an explicit no-match state. Escape closes Find first; a second Escape closes About. About has Find because its preferences dump can be long, and sharing this behavior with Log keeps the controls predictable.

The log continues to append while open. Appends preserve a reader's text selection and current search match. The view follows new output only when it was already at the bottom and the reader is neither selecting text nor searching; browsing an earlier part of the log must not jump. Closing the log removes its listener.

## Regression boundary

`test/diagnostic-text.js` exercises the real Tauri windows and system clipboard. About coverage distinguishes Copy from Copy All, checks empty selection, case-insensitive Find, match counts, both navigation directions, no-match feedback, query-field Copy, and Escape handler behavior. Log coverage opens the actual protocol log, searches protocol text, then checks that matching appends retain the current occurrence and update the count. It also checks manual selection, scroll position while browsing, Copy All after appends, and tail following. A macOS-only test invokes actual installed Edit-menu item IDs through a test-only Rust command and checks routing to About, Log, and the main editor. Keyboard handler checks dispatch DOM events so they can run with a locked desktop; physical shortcuts, native menu focus, context-menu delivery, and mouse interaction remain unverified.

The source pages are shared with Electron, so those paths should retain the same visible behavior. Validation results will be recorded here after implementation.
