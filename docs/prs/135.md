# Retire the Electron build target

Tracking issue: [#135](https://github.com/xpqz/tauride/issues/135).

The desktop distribution uses Tauri, but `npm start` still launched Electron and the build tree retained an independent Electron packaging pipeline. The supported targets are now Tauri desktop and browser-only Ride. Local start/build commands use the pinned Tauri CLI, CSS compilation no longer initializes Electron development tooling, and legacy packaging, signing and style-picker scripts are removed.

Shared version generation, Monaco bundling and browser-only packaging remain in `mk`. Buffer is an explicit dependency of desktop staging. Builds retain the project licence and generate notices for the frontend packages they ship. Active Node-style APIs in the compatibility layer remain available to frontend code and user extensions.

The desktop window adapter now contains only its Tauri implementation. Connection-page window state goes directly through that adapter, while the legacy `save-win` compatibility entrypoint remains available to extensions. Preferences F12 targets the current Preferences window through the same adapter; browser Preferences leave F12 to the browser.

Closing DevTools restores native keyboard focus to its owning webview, so Preferences still receives Escape after the inspector closes.

Tests cover shared/browser build output and attribution, clean behavior, desktop/browser F12 routing, and connection/session geometry requests. A physical native F12 regression verifies that only the Preferences window opens DevTools and that Preferences remains usable afterward. The PR records clean-install, native, browser and platform CI results.

No user preference migration, menu/keymap policy change or interpreter process-ownership change is included. The asynchronous native-services migration is tracked separately in [#136](https://github.com/xpqz/tauride/issues/136).
