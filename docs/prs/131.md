# Native UI QA and syntax colouring

Tracking issue: [#131](https://github.com/xpqz/tauride/issues/131).

The expanded native suite checks window resizing, local interpreter shutdown, rendered syntax colours and installed menu actions. The highlighting checks exposed a Monaco 0.57 regression: bracket-pair decorations override APL delimiter colours even though the editor disables bracket colouring. Monaco's standalone model configuration does not inherit that editor option, and changing indentation can restore its default.

Monaco initialization now disables those decorations on every new model and restores that setting if an options update re-enables it. The guarded public event listener covers Session, ordinary and file-backed editors, and preference previews; it is removed when the model is disposed. A regression test failed against the initial one-shot fix, demonstrating why initialization alone was insufficient.

## Coverage

- Resize docked and floating editors, Session, Preferences and About through small, large and restored sizes. Check actual viewport and Monaco geometry, retained text and selection, usable controls, native typing and subsequent Session execution.
- Repeatedly close local Sessions through native close, use physical Cmd-W for one Session and Cmd-Q for several, and close while an interpreter is busy. Verify recorded interpreter PIDs and process identities disappear before harness teardown, while surviving Sessions still execute. Cmd-Q must exit normally.
- Check rendered APL/APLAN delimiters after edits and undo, local variables and dfn arguments after theme changes, and embedded LF/CR source markers and read-only behaviour. Check Session, ordinary editors and file-backed models after indentation preference changes.
- Dispatch installed native View and Preferences menu items. Verify checked state, visible bars, Session wrapping, focus and helper-window cancellation.
- Exercise the process-tracking helper with owned child processes, including leak detection and protection against a changed PID identity.

`npm run test:ui-qa` selects the campaign. [The native testing guide](../ui-testing.md) documents prerequisites, full-suite runs, rebuilding and platform limits. Test menu probes are confined to the `ui-tests` feature.

The installed-menu probe recognizes macOS's observed rename from `Preferences...` to `Settings…`. Missing-item diagnostics include the installed IDs and labels, and menu polling preserves WebDriver transport errors instead of reporting them as missing menu items. No production menu behaviour changed.

## Validation

- `npm run test:unit`: all 256 tests passed, including four new process-helper checks.
- The focused highlighting, installed-menu and interpreter-lifecycle run passed all 11 cases against a freshly built native binary.
- `node mk zf` and `node tools/zf-smoke.js _/zf`: passed, with a real Monaco worker RPC, folding checks, no missing assets and no console errors.
- Independent reviews covered the tests, process ownership, menu bridge and model event lifecycle, with no outstanding findings.
- Native screenshots of small/large docked Session/editor layouts, resized Preferences and About were visually inspected. Pane sizes, selection and controls remained usable.
- The final process inventory contained no new Tauride, Dyalog or Dyalog helper processes relative to the starting inventory. Pre-existing processes were left untouched.

The full native run completed with 84 passing cases, one startup-hook timeout and one Preferences-menu lookup failure. The latter exposed the native label rename described above; both menu cases passed after correcting the test bridge and rebuilding. The language-bar case blocked by startup also passed on a focused rerun. All 86 native cases therefore have passing results across the full and focused runs, but this was not a clean single full-suite pass. Fifteen native cases are new.

Three runs encountered an intermittent WebDriver startup timeout before a test began, including one run of the unchanged baseline. Both element lookup and prompt-readiness requests have stalled in the macOS WebDriver/WebKit callback path. The root cause remains unproven and is tracked in [#132](https://github.com/xpqz/tauride/issues/132). No startup retry or timeout increase was added to conceal the failure.

Local native checks use macOS and Dyalog 21.0.54424. Windows and Linux native input and lifecycle behaviour require validation on those platforms; current CI covers cross-platform builds, the Node suite, browser smoke and a Linux connection subset.
