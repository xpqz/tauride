# Remove completed agent confirmations reliably

Tracking issue: [#139](https://github.com/xpqz/tauride/issues/139).

Hover during dismissal can restart a sticky confirmation's animation and leave its obsolete Run/Deny buttons visible after the agent disconnects or loses control. A controlled browser mouse event reproduced this with the real Toastr and jQuery handlers. It establishes the dismissal defect without claiming that physical hover caused the earlier intermittent native-suite failure.

An answered confirmation now removes its hover handlers, finishes the current animation and clears queued effects before Toastr's forced clear. Toastr still removes the toast and cleans its container bookkeeping. The change applies to cancellation, Run, Deny and the existing timeout path; unrelated notifications retain their behavior. The existing one-shot answer guard, request timer cleanup and abort-listener cleanup remain in place.

Both native regressions exercise hover during cancellation with Run focused, for socket reconnect and control revocation. They retain the old Run/Deny elements and activate them while a fresh confirmation is pending, check that an ordinary notification survives, and use a real WebDriver Run click followed by repeated retained-button activations. Only one fresh input may reach the interpreter. Both cases failed at the toast-removal assertion before the fix.

Validation: both native regressions pass against a freshly staged build with the fix, after failing against the unchanged production code. All 296 display-independent tests pass; JavaScript syntax and whitespace checks pass.
